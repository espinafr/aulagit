01

O que é controle de versão?

O controle de versão — conhecido pelas siglas VCS (Version Control System) ou SCM (Source Control Management) — é um sistema que rastreia o histórico de alterações em arquivos e coordena o trabalho de várias pessoas sobre eles. Na prática, ele registra cada modificação de um projeto ao longo de uma linha do tempo.

No desenvolvimento de software moderno, o controle de versão é considerado essencial. Veja os cinco motivos principais:

1 · Trabalho em equipe sem bloqueios

Sem um VCS, quando várias pessoas editam o mesmo arquivo, o trabalho pode ser sobrescrito (alguém perde o que fez) ou o arquivo fica bloqueado para edição, travando a produtividade. O controle de versão deixa todos trabalharem em paralelo e combina as alterações de forma organizada.

2 · Histórico completo e recuperação (backup)

O sistema registra o que mudou, quando e por quem. Se um bug aparece, a equipe volta atrás e recupera o estado exato do passado — e ainda descobre a origem da falha comparando versões.

3 · Segurança para experimentar com branches

As ramificações (branches) são linhas paralelas de desenvolvimento. Elas isolam um trabalho — nova funcionalidade, correção ou teste — sem risco de quebrar o código principal que já está em produção.

4 · Redundância contra falhas (distribuído)

Em sistemas distribuídos como o Git, cada pessoa tem uma cópia completa do repositório com todo o histórico na própria máquina. Não depende de rede constante e, se o servidor central falhar, o projeto é restaurado a partir de qualquer cópia local.

5 · Qualidade e agilidade

Com a complexidade crescente dos softwares, controle de versão, automação e colaboração transparente são o único caminho viável para garantir qualidade, agilidade e eficiência na entrega.

02

Git × GitHub: qual a diferença?

Eles andam lado a lado, mas são ferramentas distintas e complementares. A forma mais simples de memorizar: o Git é a ferramenta; o GitHub é a plataforma.

AspectoGitGitHub
O que éSoftware de controle de versão distribuído, de código abertoServiço online que hospeda repositórios Git
Onde rodaLocalmente, no seu computadorNa nuvem
FunçãoRastrear o histórico e tirar "fotos" (commits)Centralizar, compartilhar e colaborar
Recursos extrasBranches, commits, log — via terminalPull requests, issues, Actions, portfólio
PapelCliente localServidor remoto
💡

Resumo da relação: você pode usar o Git sozinho, offline, sem nunca abrir o GitHub. Mas quando quer colaborar ou publicar seu código, usa o git push para enviar seus arquivos e histórico para um repositório hospedado no GitHub.

03

Criando a conta e configurando o Git

1 · Criando a conta no GitHub

  1. Acesse o site oficial: entre em github.com.
  2. Inicie a inscrição: clique em Sign up, no canto superior direito.
  3. Preencha os dados: e-mail, uma senha segura e um nome de usuário (username).
  4. Verificação: resolva o CAPTCHA quando solicitado.
  5. Escolha do plano: selecione o Free — repositórios ilimitados para uso pessoal e colaborativo.
  6. Confirme o e-mail: abra sua caixa de entrada e ative a conta.

2 · Configurando o Git no seu computador

Depois de criar a conta, identifique suas alterações locais para que o Git saiba quem fez cada commit. Abra o terminal (Linux/macOS) ou o Git Bash (Windows) e rode:

bash · configuração global
git config --global user.name "Seu Nome de Usuário"
git config --global user.email "seu-email@exemplo.com"
# use o MESMO e-mail cadastrado na sua conta do GitHub

3 · Autenticação para o git push

O GitHub não aceita senhas tradicionais na linha de comando. Configure uma das opções seguras abaixo:

🔑

Personal Access Token (PAT)

Gerado em Settings › Developer Settings › Personal Access Tokens. Substitui a senha ao rodar git push.

🔐

Chave SSH

Cadastre uma chave SSH na conta para autenticar sem digitar credenciais toda vez.

✅

Com a conta criada, o Git configurado e a chave/token definida, sua máquina está pronta para git init, git add, git commit e git push.

04

Repositório e o primeiro projeto

Um repositório (o repo) é uma pasta especial que guarda todos os arquivos do projeto mais o histórico completo de alterações. Como o Git é distribuído, você tem uma cópia idêntica de tudo na sua máquina local.

Método 1 · Criar do zero (git init)

bash · novo projeto
cd caminho/da/sua-pasta
git init
Initialized empty Git repository in .../.git/
# dica: git init nome-do-projeto cria a pasta e inicializa de uma vez

A partir daí, a pasta .git é criada e o Git passa a monitorar qualquer modificação de arquivos naquele diretório.

Método 2 · Clonar um projeto existente (git clone)

bash · baixar da nuvem
git clone https://github.com/usuario/projeto.git
Cloning into 'projeto'...
# baixa TODOS os arquivos + TODO o histórico de uma vez
05

O fluxo de trabalho: as Três Árvores

Para registrar versões, seu código passa por um ciclo entre as três "áreas" do Git — as Three Trees:

O ciclo prático, passo a passo

  1. Verifique o estado: veja o que mudou e ainda não foi salvo.
    passo 1
    git status
  2. Adicione à preparação: diga ao Git o que entra no próximo commit.
    passo 2
    git add README.md   # um arquivo específico
git add .           # todas as modificações da pasta
  3. Salve a versão (commit): uma "foto" do código com uma mensagem clara.
    passo 3
    git commit -m "Cria o arquivo de documentação README"
  4. Acompanhe o progresso: veja a linha do tempo dos salvamentos.
    passo 4
    git log
06

Conectando o repositório local ao GitHub

Para enviar seu repositório local à nuvem e deixá-lo acessível no GitHub, siga as etapas finais:

  1. Crie o repositório remoto: no GitHub, clique em New, dê um nome e confirme.
  2. Copie a URL do repositório remoto recém-criado.
  3. Vincule os dois repositórios no terminal local.
  4. Defina a ramificação principal como main.
  5. Envie o código local para a nuvem.
bash · sincronizar com o GitHub
git remote add origin https://github.com/seu-usuario/seu-projeto.git
git branch -M main
git push -u origin main
Enumerating objects... done.
Branch 'main' set up to track remote branch 'main' from 'origin'.
🚀

Pronto! Seu repositório local está criado, ativo e sincronizado com o GitHub. A partir daqui, todo novo commit pode ser enviado com um simples git push.
